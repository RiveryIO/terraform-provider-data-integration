Reference
API / MongoDB field → Terraform schema modifier
The Go client returns every field as map[string]any. The provider's apply() picks which ones enter environmentModel, and the schema decides how Terraform tracks them. The modifier follows from the API's behaviour for that field — not from preference.
API behaviour Terraform modifier Example fields Plan effect
User sets it, required Required environment_name, connection_name, display_name Plan shows diff on any change. Terraform errors if absent.
User sets it, optional Optional description Absent from state when not configured. Plan shows diff on add/remove.
User sets it; API fills a default if absent Optional + Computed color, is_default If user omits it, API value is stored in state. User can later override.
Server-assigned on create, never changes Computed + UseStateForUnknown id, cross_id, created_at, public_key, user_created Shows (known after apply) on first apply only. Clean plan forever after.
Server-assigned on every write Computed only updated_at, updated_by Shows (known after apply) after every mutating apply — accurate because value genuinely changes.
Immutable after create — API rejects changes Required + RequiresReplace connection_type, river_type, key_name Plan shows destroy + recreate on any change. Prevents API 400.
Credentials — written once, never returned Required + WriteOnly parameters_json, private_key Value written to API but never stored in state. Drift detection impossible.
Opaque JSON blob, config-authoritative Required (or Optional + Computed) properties_json, settings_json, config_json Provider stores and diffs the raw JSON string. Server may enrich it — import-verify needs ImportStateVerifyIgnore.
Typed nested object (API rejects free-form JSON) nested block (Required attrs) connection_settings.{connection, datasource_id, storage_type, default_bucket} Each sub-field tracked individually. Plan shows per-field diffs.
Internal soft-delete guard internal Not in schema is_deleted, is_delete_lock Read inline in Read() / Delete(). Never touches environmentModel.
Implicit from provider config internal Not in schema account, account_id Carried by the client from provider config. Redundant to expose per-resource.
Soft-delete audit trail internal Not in schema deleted_at, deleted_by, error_message Only meaningful after deletion — resource is removed from state at that point anyway.
Ephemeral / regenerates each write internal Not in schema step_id, presigned_url step_id changes every PUT — storing it causes perpetual diff. presigned_url has a 1-hour TTL.
Async operation envelope internal Not in schema operation_id, operation_type, run_id, status, last_update_date DELETE response body only. Describes the queued job, not the resource state.
Managed as a separate resource internal Not in schema variables Each key–value is its own boomi_variable resource. Embedding them here would require a map attribute and lose per-variable lifecycle.
