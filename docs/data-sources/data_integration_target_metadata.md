# Discover a target's containers

Lists the top-level containers a target warehouse connection can see — Snowflake databases, BigQuery
datasets, Databricks catalogs — so a data flow's destination is picked from the real warehouse
instead of typed in blind.

## How it works

`boomi_data_integration_target_metadata` drives the same discovery the console's target picker uses: the platform opens a
connection to the warehouse and lists its containers.

- `names` — the flat list of names (databases, datasets, or catalogs, depending on `target_type`).
  Covers the common case directly.
- `result_json` — the raw operation result, passed through unmodified. Decode it with `jsondecode()`
  for warehouses that return an array of objects instead of a flat list.

## Example Usage

```terraform
# Discover the top-level containers of a TARGET warehouse connection — Snowflake
# databases, BigQuery datasets, or Databricks catalogs — from the live
# connection, so a data flow's target location is chosen from the real warehouse
# rather than hand-typed. Verified against Snowflake in integration (see the
# provider README).

# List the databases of a Snowflake target connection.
data "boomi_data_integration_target_metadata" "warehouse" {
  environment_id = var.environment_id
  connection_id  = boomi_data_integration_connection.snowflake_target.id
  target_type    = "snowflake" # snowflake -> databases, bigquery -> datasets, databricks -> catalogs

  timeouts {
    read = "3m"
  }
}

# `names` is the flat list of database/dataset/catalog names.
output "warehouse_databases" {
  value = data.boomi_data_integration_target_metadata.warehouse.names
}

# `result_json` is the raw operation result, passed through unmodified — decode
# it with jsondecode() for warehouses that return an array of objects.
output "warehouse_result_raw" {
  value = jsondecode(data.boomi_data_integration_target_metadata.warehouse.result_json)
}
```

## Schema

### Required

- `connection_id` (String) The target warehouse connection (cross_id) to introspect.
- `target_type` (String) The target warehouse type. One of "snowflake" (lists databases), "bigquery" (lists datasets), or "databricks" (lists catalogs). Sent as the pull-request datasource_id and mapped to the matching task verb.

### Optional

- `environment_id` (String) Environment ID. Falls back to the provider default.
- `timeouts` (Block, Optional) How long to wait for the target discovery to finish. (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `id` (String) Synthetic id: "<connection_id>:<task>" (task is get_databases/get_datasets/get_catalogs).
- `names` (List of String) The discovered container names (databases/datasets/catalogs) when the warehouse returns a flat array of strings. Empty when the warehouse returns a richer shape — use `result_json` in that case.
- `result_json` (String) The raw operation result payload as a JSON string, passed through unmodified. For Snowflake this is a JSON array of database-name strings; for BigQuery/Databricks it may be an array of objects. Decode with `jsondecode()`.

- `read` (String) Go duration string (e.g. "3m", "90s") bounding the discovery poll. Default "3m".
