# PR Risk Assessment

Score 1–10. **Auto-approve threshold: ≤ 4** (handled by the `pr-risk-assessor` Lambda).

## Low risk (1–4) — auto-approve
- Documentation, comments, README changes only
- Test additions (`tests/`) with no production-code change
- New `rivers/*.json` data-flow definitions (declarative config consumed by `riverctl`)
- Edits to an existing `rivers/*.json` that change only description/labels/scheduling
- Config/env-variable changes with no logic change
- Dependency version bumps (patch/minor, no breaking change)

## Medium risk (5–7) — manual review
- Changes to `rivery_client.py` or `riverctl.py` logic (the reconcile loop / API client)
- New `riverctl` subcommands or state-file format changes
- Refactors within a single module

## High risk (8–10) — manual review, careful
- Changes to auth/token handling or credential resolution
- Changes to write semantics (`_deep_merge`, `_strip_forbidden`, create/update/delete paths)
- Changes to `bitbucket-pipelines.yml` (CI/CD) or the auto-approve config itself
- Anything that could mutate production (non-integration) Rivery data flows
- Removing/renaming a public function or the state-file contract
